# Application contract

Entrypoint: `sh app/launch.sh [--root ROOT] [--check|--headless-test] [--seconds N] [--mute] [--no-software-dmd] [--profile desktop|cabinet]`. Direct system-Python entry `python3 -B app/launch.py` supports the same arguments (including installer's `--root`).

- Default interactive, native SDL/X11 color DMD on (640x160 on second detected display or upper-left playfield), audio on; external DMD off. `--seconds` exits owned VPX via F4 and requires matching backend STOP and zero outputs. No fake runtime evidence.
- `--check` checks installed bytes/config/executables only, never imports game code or starts output; it is not runtime/hardware qualification.
- `--headless-test` runs real CCC attract/ticks/render/IPC WPC input mapping, dummy video/audio, physical DMD off; verifies actual nonblank RGB256x64 frame and protocol STOP. It never launches VPX. Existing saves are copied into this fresh run's `selftest-saves/`; template initialization/game callbacks can write that sandbox, never installed saves. Cleanup does not persist selftest gameplay.
- Root: `CCC_INSTALL_ROOT` or parent of this app directory. `settings.json` schema1 fields per installer contract plus `software_dmd` (boolean default true), optional `dmd_position: [x,y,pixel_size]`. `dmd_server` strictly null or `127.0.0.1:PORT`: compatibility-specific opt-in, no automatic physical hardware detection or server lifecycle. Port reachable only checked on an actual enabled launch.
- Ignore stale `settings.install_root`; relocating the application is supported but the patched table must be rebuilt for the new concrete root because embedded VBS reads its active-ipc pointer there.
- `python3 app/build_table.py SOURCE.vpx SOURCE.vbs STAGING/tables --install-root FINAL_ROOT`. Exact SHA256 pair mandatory. Also accepts `--table SOURCE.vpx --script SOURCE.vbs --output-table STAGING/tables/CCC-native.vpx --output-script STAGING/tables/CCC-native.vbs --install-root FINAL_ROOT`; no CLI hash override. Python API `build_table(source_vpx,source_vbs,destination,install_root=None)` returns manifest. Emits `CCC-native.vpx`, `CCC-native.vbs`, `build-manifest.json`. Never distribute the resulting user-supplied table/script. Supports stage path distinct from final pointer root. Fails existing outputs; installer should use fresh staging.
- The controller and WPC mapping originate in the reviewed bridge. Mapping provenance is retained; no game/table/media copied into app. Licence auditor must resolve legacy mapping/controller provenance separately; a generated-code header is not third-party permission.
- `config/VPX.ini` can be only a comment. Runtime starts from machine global VPX settings (read only), overlays private INI, disables external DMD/B2S/DOF/PUP, picks detected current dimensions and leaves table camera default. Cabinet camera only explicit portrait `--profile cabinet`.
- Private HOME/XDG config for both children, discovered Pulse socket/cookie or normal ALSA, never changes system display/audio config. Runtime forces FakePinPROC before construction, disables desktop key mapping and updater/shutdown shortcuts. VPX owns standard keyboard controls. Hotkeygen temporary context (if installed) restores prior context only when still owned.
- Saves in root/saves only; source personal data is not imported. Copy/import saves must remain explicit installer operations. Runtime preserves authentic templates and original post-draw color rendering, samples logical128x32 centers and emits solid2x2 physical grid256x64.
- Exclusive root launch lock; existing lock or another VPX is refused. Failure cleanup reaps only own process groups, removes only own pointer and restores only own context. SIGINT/SIGTERM triggers normal exit then bounded cleanup; errors are nonzero, no broad process kills.

Offline tests: `python -m unittest discover -s app-tests -v` from package root. They require no native runtime/game/media. Actual isolated installed-root headless then visible desktop/audio/VPX qualification belongs to the release owner; fixture tests do not certify it.
